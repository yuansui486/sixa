# Mac 本机密钥与旧版迁移

从 1.0.11 起，Mac 使用本机文件保存应用内部加密密钥，不再依赖临时签名应用的钥匙串访问授权。Windows 仍使用 Credential Manager。用户口令保护的可逆恢复包不受影响。

## 用户操作

新安装不需要钥匙串授权。升级用户若已有历史数据，第一次打开可能出现一次旧密钥读取授权：请输入 **Mac 登录密码**，点击“允许”即可，不是私匣账号密码。迁移完成后，重启及后续升级不再读取该密钥的钥匙串条目。

迁移保留原密钥的 32 字节内容，不重新加密、不删除历史文件，也不删除钥匙串旧条目。如果拒绝授权、钥匙串锁定、密钥不存在或无法解密原有登录数据，应用停止迁移并说明原因，不生成替代密钥。请解锁“登录”钥匙串，再手动打开应用。不要删除 `LocalDesensitization` 条目。

旧版登录会话和设备标识仅在无需系统弹窗时尝试迁移；无法读取时需要重新登录。已存在的 `db/auth-state.enc` 保持原有会话和设备标识。

## 文件与保护范围

应用目录：`~/Library/Application Support/LocalDesensitization/`。

| 路径 | 用途 |
| --- | --- |
| `secrets/internal-key-v1` | 32 字节内部密钥，文件权限 `0600` |
| `secrets/key.lock` | 防止并发迁移的进程锁，文件权限 `0600` |
| `db/local-key-v1` | 已采用本机密钥的标记与加密校验数据，不包含密钥 |
| `db/auth-state.enc` | 使用内部密钥加密的登录会话与设备标识 |

`secrets` 目录权限为 `0700`。读取时检查所有者、权限和文件类型，拒绝符号链接及多重硬链接；写入使用临时文件、同步落盘和禁止覆盖的原子发布。密钥缺失或损坏时不回退到旧钥匙串，不自动重置，避免用错误密钥覆盖历史数据。

这个方案依赖当前 Mac 账号的文件权限，**不能防御以同一用户身份运行的其他程序读取密钥**，保护弱于按应用授权的钥匙串。设备应使用独立账号并开启 FileVault。密钥不发送给服务端，不进入日志、WebView 或 MCP 响应。

备份历史数据时应安全备份整个应用目录，包括 `secrets`；只备份任务文件不足以恢复历史数据。不要单独上传或分享密钥文件。升级不会主动清理密钥，不建议降级到 1.0.10 及更早版本，因为旧版只识别钥匙串方案。

## 失败与自动启动

桌面启动前记录启动门禁，成功初始化本机通信后解除。失败或停留在系统授权窗口时，MCP 返回 `STARTUP_BLOCKED`，`retryable=false`，不循环拉起应用。用户手动启动成功后自动恢复；标记不包含敏感数据。

## 验证

Mac CI 覆盖新安装、迁移、拒绝授权、缺失/错误密钥、原密文保留、权限异常、链接拒绝、并发锁与重启。另用临时钥匙串条目执行真实迁移，并删除测试条目后确认本机密钥可继续解密。最终 DMG 中的应用还会在钥匙串锁定后重启，验证私有文件权限、密钥保持不变和 MCP 可连接。CI 不下载生产模型。
